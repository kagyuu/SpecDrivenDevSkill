# 【テストID】T028

## 【目的】

* `docs/P006-test-plan.md` §3「運用(再起動耐性)」の観点を自動化する。CR-003で追加する非冪等なDDL(`ALTER TABLE RESERVATIONS ADD COLUMN attendee_count INTEGER`)を含むマイグレーション一式に対して、**同一のデータベースファイルに `init_db()` を2回連続で実行しても2回目が成功する**こと、および2回目の実行後もスキーマ・既存データが壊れないことを確認する。
* あわせて、CR-003以前(`SCHEMA_MIGRATIONS` テーブルを持たず、0001・0002だけが適用済み)のDBから起動した場合にも正常に移行できることを確認する。

* `server/app/db/connection.py`、`server/app/db/migrations/*.sql`

## 【実行手順】

1. 新規DBファイルに対して `init_db()` を実行する(1回目)。
2. 同じDBファイルに対して `init_db()` を再度実行する(2回目=再起動相当)。
3. 2回目の実行後、`PRAGMA table_info(RESERVATIONS)` に `attendee_count` が存在することを確認する。
4. 1回目と2回目のあいだに投入したデータが2回目の実行後も残っていることを確認する。
5. 「CR-003以前のDB」を模擬したファイルに対して `init_db()` を2回実行する。
