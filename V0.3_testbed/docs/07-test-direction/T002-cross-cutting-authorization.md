# T002: 権限をまたぐアクセス制御確認

> V0.3ルールで再生成。IDは本ファイル名・目次と一致する T002 表記を最初から使用している。

あなたはテスト担当です。以下の1テストタスクだけを実施してください。

【テストID】T002
【目的】U002(会議室)・U003(予約)・U004(ユーザー)にまたがる管理者専用API群に対し、一般ユーザーが一貫して`403`で拒否されることを確認する(`docs/01-requirement.md`テスト方針「権限まわりは結合テストで必ず確認する」に対応)。
【参照テスト計画】`docs/05-test-plan.md` 2章(認可エラー)、`docs/01-requirement.md`テスト方針
【対象モジュール】`server/app/common.py`(require_admin)、`rooms.py`, `users.py`
【前提条件】ビルド成功。
【使用するテストデータ】seedデータ(u001/password01, 一般ユーザー)
【事前準備】一般ユーザーでログインしCookieを保持する。
【実行手順】
1. u001でログインする。
2. `POST /api/rooms`, `PUT /api/rooms/{id}`, `DELETE /api/rooms/{id}` を呼び、いずれも403であることを確認する。
3. `GET /api/users`, `POST /api/users`, `PUT /api/users/{id}`, `DELETE /api/users/{id}` を呼び、いずれも403であることを確認する。
4. 他人(u002)が作成した予約に対する `PUT`/`DELETE` が403であることを確認する。
【実行コマンド】`cd server && python3 -m unittest tests.system.test_t002_cross_cutting_authorization -v`
【期待結果】すべて403 + 共通エラー形式。
【合否判定基準】全アサーション成功。
【失敗時に記録する内容】どのエンドポイントが403以外を返したか。
【修正禁止事項】T001と同様。
【次タスクへ進む条件】結果がテスト記録に記載された時点。

重要:
- アプリケーションコードを修正しないでください。
