あなたはテスト担当です。以下の1テストタスクだけを実施してください。

【テストID】T004
【目的】`docs/03-backend-spec.md` 5章(エラーハンドリング共通方針)、および4章「予約系」の参加者ID実在チェックが、代表的な異常系リクエストで一貫して守られていることを確認する。
【参照テスト計画】`docs/05-test-plan.md` 2章(主要異常系)
【対象モジュール】`server/app/main.py`(共通例外ハンドラ)、各routers
【前提条件】ビルド成功。
【使用するテストデータ】不正なJSONボディ、存在しないID、必須項目欠如のリクエスト、存在しない参加者IDを含む予約作成リクエスト
【事前準備】adminでログインしCookieを取得する。
【実行手順】
1. 存在しないパス(`GET /api/does-not-exist`)にアクセスし404 + 共通形式を確認する。
2. 不正なJSON(パース不能な文字列)を`POST /api/auth/login`に送信した場合のレスポンスを確認する。
3. 存在しない予約ID(`GET /api/reservations/999999`)で404を確認する。
4. 必須項目を欠いた予約作成リクエストで400 + 共通形式を確認する。
5. 存在しない参加者ID(`participant_ids: [999999]`)を指定して予約作成リクエストを送り、`docs/03-backend-spec.md` 4章「予約系」の規定どおり `400 VALIDATION_ERROR` になること(`500`にならないこと)を確認する。
6. `capacity: 0`(1未満)を指定して`POST /api/rooms`を呼び、`docs/02-frontend-spec.md` 1章S06「収容人数: 必須。1以上の整数」の規定どおり `400 VALIDATION_ERROR` になること(`500`にならないこと)を確認する。
【実行コマンド】`cd server && python3 -m unittest tests.system.test_t004_error_handling -v`
【期待結果】1,3,4,5,6はいずれも仕様通り(404/400 + 共通エラー形式)であること。2は、`docs/03-backend-spec.md` 5章の「未捕捉例外は500」に該当するため500になること自体は仕様の範囲内だが、共通エラー形式(`{"error":{...}}`)を維持していることを確認する。
【合否判定基準】1,3,4,5,6がPASSし、2で共通エラー形式が維持されていること。ステータスコードが期待と異なる、または共通形式が崩れる(生のスタックトレース等がレスポンスボディに含まれる)場合はFAILとする。
【失敗時に記録する内容】実際のステータスコード・レスポンスボディ。
