# テスト計画

## 目的

* テスト計画を作成して、フロントエンドおよびバックエンドをどのような単位でどのような観点でテストするかを確定する。

## インプット文書

* `docs/01-requirement.md`
* `docs/02-frontend-spec.md`
* `docs/03-backend-spec.md`
* `docs/04-impl-plan.md`

## アウトプット文書

* `docs/05-test-plan.md`

### アウトプットの記載内容

* 各テストの目的・観点。
  * V字モデルに沿って、以下の4つのテストレベルに分けて目的を明確化する

| テストレベル | 目的 |
| --- | --- |
| 単体テスト | ユーザインタフェース設計書、システム詳細設計で定義した、画面、APIが、単体で仕様どおりに動くか |
| 結合テスト | ユーザインタフェース設計書、システム詳細設計で定義した、画面、APIが、連携して仕様通りか |
| システムテスト(総合テスト) | システム要件定義書の要件・非機能要件を満たしているか |
| 受入テスト | 発注者・利用者・運用者の視点で、本番相当環境で問題なく使えるか |

  * テストの観点を明確化して、どのテストレベルで行うかを明確化する
    * 機能観点: ユーザインタフェース設計書、システム詳細設計の各APIエンドポイント・各画面ごとの具体的なテストケース(正常系 + 主要な異常系: バリデーションエラー、Not Found、認可エラーなど)
    * 非機能観点: 性能・負荷・セキュリティ・運用(ログ監視)など
* そのほか、外部APIのモック方針、テストデータの準備方法など、テスト遂行上の技術的な決め事を記載する
* なお、ここで作るのは、テストとして何を行うかの「テスト計画」であり、個々のテストケースの実装や具体的なパラメータは プログラム実装定義 や 結合テスト定義 で、この文書をもとに実装指示を別途作成する。

### アウトプットを参照する文書

アウトプットの記載内容は、次の文書を作成できる程度に具体的であること

* `docs/06-impl-direction.md` (目次 OKF形式)
* `docs/06-impl-direction/U000-{sprint-name}.md` (各スプリントの実装指示、000はスプリント番号(実行順))
* `docs/07-test-direction.md` (目次 OKF形式)
* `docs/07-test-direction/T000-{test-name}.md` (000はテスト番号(実行順)、test-name はテスト名)
