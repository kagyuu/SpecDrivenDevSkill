# 変更要求作成

## 目的

* 納品後(またはPlan Loop Step完了後)にユーザーから寄せられた改善・修正の要望を、`docs/CR.md` に変更要求(CR)として整理する。
* ここでは要求の整理のみを行い、設計・実装の修正はP902以降で行う。

## インプット文書

* ユーザーからの要望(会話・issue・メールなど、フォーマットは問わない)
* 既存の `docs/CR.md` (あれば)
* `docs/ArchitectureHandbook.md` / `docs/ADR.md` (影響範囲を見積もる参考として)

## アウトプット文書

* `docs/CR.md`

### アウトプットの記載内容

* `TEMPLATE-CR.md` の構成に則り、要望1件につき1つのCR-NNNとして整理する。複数の要望が混ざっている場合は分割する。
* 状態は `未対応` から始める。優先度は人間の指示があればそれに従い、なければ内容から妥当な優先度を仮置きし、末尾に "★FIXME★" を付けて人間の確認を促す。
* 既存の `docs/ADR.md` に抵触する要望(既に採用済みの決定を覆す要望)であれば、その旨を「影響が想定される範囲」に明記する。

### アウトプットを参照する文書

* `docs/P902-*` (要件定義更新) が、対応するCRの内容にもとづき `docs/P001-requirement.md` を更新する。

## 動作

* 共通指示以外は特になし
* 本フェーズはRefactor(修正)のみで実行される、Plan Loop Step / Executor / Reviewer Loop / Closing の各Stepでは実行しない。
