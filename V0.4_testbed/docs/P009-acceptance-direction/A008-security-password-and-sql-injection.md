# 【テストID】A008

## 【目的】

* パスワードが平文でDB・APIレスポンスに含まれないこと、およびSQLインジェクションを試みる入力に対してアプリケーションが安全に動作すること(パラメータ化クエリが使われていること)を確認する。

## 【参照テスト計画】

* `docs/P006-test-plan.md` §3(セキュリティ)

## 【対象モジュール】

* `server/app/repositories/*.py`(全Repository、プレースホルダ使用の確認)、`server/app/api/users.py`

## 【前提条件】全モジュールビルドが成功していること

* U001〜U004が完了していること。

## 【使用するテストデータ】

* SQLインジェクションを想定した文字列(例: `employee_id = "E0001' OR '1'='1"`)をログインリクエストの各フィールドに投入する。

## 【事前準備】

* テスト用DBを初期化する。

## 【実行手順】

1. `GET /api/users` のレスポンスを確認し、`password_hash` に相当するフィールドが含まれていないことを確認する。
2. DBファイルを直接参照し、`users.password_hash` が平文パスワードと一致しない(ハッシュ化されている)ことを確認する。
3. SQLインジェクション文字列を `employee_id` に入れて `POST /api/auth/login` を呼び、異常終了(500)やログイン成功(意図しない認証バイパス)が起きないことを確認する。

## 【実行コマンド】

* `cd server && uv run pytest tests/acceptance/test_a008_security.py -v`

## 【期待結果】

* 手順1: レスポンスにパスワード関連フィールドが含まれない。
* 手順2: `password_hash` が平文パスワードと一致せず、既知の安全なハッシュアルゴリズムのタグ付き形式であること。
  * ★P202-F003修正★ 当初の期待結果は `docs/P003-backend-spec.md` §3・ADR-004が指定するbcrypt形式(`$2b$...`)を前提に書かれていたが、本サンドボックスの制約(`docs/P101-impl-context.md`)によりbcryptパッケージを導入できず、承認済みの代替として `hashlib.scrypt` による `scrypt1$<salt hex>$<derived hex>` 形式を全システムで一貫して採用している(`server/app/core/password.py`)。この代替は実装当初から承認済みであり、セキュリティ上の欠陥ではない。よって本手順の合否判定は「平文と異なり、`scrypt1$` から始まるタグ付きハッシュ形式であること」とする。
* 手順3: `401 AUTH_INVALID_CREDENTIALS`(500エラーにならない、かつ認証バイパスされない)。
