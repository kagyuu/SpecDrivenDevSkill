- 実際の結果: `login_failed`イベントのログ出力が一切無い(標準出力はuvicornのアクセスログのみ)。`app/services/auth_service.py`にはログ出力コードが存在しない。
- 失敗ログ抜粋:
  ```
  AssertionError: expected at least one JSON Lines log record with event='login_failed'
  captured stdout:
  INFO:     127.0.0.1:62108 - "GET /health HTTP/1.1" 200 OK
  INFO:     127.0.0.1:62111 - "POST /api/auth/login HTTP/1.1" 401 Unauthorized
  ```

- 影響がありそうなモジュール: `server/app/services/auth_service.py`(`login`関数)、`server/app/logging_utils.py`(呼び出し側の追加が必要)
- テスト指示との矛盾の疑い: **検討したが「なし」と判断した。** `docs/P003-backend-spec.md` 6章は「警告レベル(WARNING)で出力するもの: 認証失敗の連続発生」と記載しており、文言だけを見ると「連続発生(N回以上)」を要求しているようにも読めるが、(1) P001〜P003のいずれにも具体的なしきい値Nの記載が無く実装不能である、(2) 同章の直後の★ACCEPTED★注記は「アカウントロック機能」の要否を検討した結果であり、対象はロック機能の要否であって「ログ出力のしきい値」ではない、(3) 「ログ出力のみ行い、自動ロックは実装しない」という文の対比構造から、単純に「(N回のロックはしないが)ログだけは出す」という意図と読むのが自然、と判断した。しきい値の実装自体がそもそも不可能(未定義)なため、「毎回ログを出す」が唯一実装可能な解釈である。よってこれはテスト指示側の誤りではなく、実装側の未実装(U005-T5で明示的にスコープ外として先送りされていた)による genuine な欠陥として扱う。
- 次工程への申し送り: P202へ。`auth_service.login()`が`InvalidCredentialsError`を送出する箇所で`log_event("WARNING", "login_failed", ...)`を呼び出す実装を追加する。
