# 【テストID】A002

## 【目的】

* 一般ユーザーが管理者専用の画面・APIにアクセスできないことを、全該当箇所について横断的に確認する(`docs/P001-requirement.md` テスト方針「権限まわりは結合テストで必ず確認する」に対応。個別スプリント内の確認(T005, T015等)を横断してもう一段広い範囲で再確認する)。

## 【参照テスト計画】

* `docs/P006-test-plan.md` 2.4節、3章(セキュリティ観点)

## 【対象モジュール】

* `client/` 全体、`server/` の `rooms.py`, `users.py`(管理者専用エンドポイント)

## 【前提条件】全モジュールビルドが成功していること

* U001〜U005すべてが完了していること

## 【使用するテストデータ】

* 一般ユーザーアカウント1件

## 【事前準備】

* 一般ユーザーでログインする

## 【実行手順】

1. `/admin/rooms`、`/admin/users` へ直接URLアクセスする
2. `POST /api/rooms`, `PUT /api/rooms/{id}`, `DELETE /api/rooms/{id}` を直接呼び出す
3. `GET /api/users`, `POST /api/users`, `PUT /api/users/{id}`, `DELETE /api/users/{id}` を直接呼び出す
4. `GET /api/rooms?include_inactive=true` を呼び出す

## 【実行コマンド】

* `cd client && node --test tests/acceptance/test_authorization_crosscheck.js`

## 【期待結果】

* 手順1: いずれも403画面が表示される
* 手順2・3: いずれも403 `FORBIDDEN`
* 手順4: 200だが `include_inactive` は無視され有効な会議室のみ返る(`docs/P002-frontend-spec.md` 4.4節)

## 【合否判定基準】

* 上記すべてを満たせばPASS。1件でも管理者専用機能に一般ユーザーがアクセスできてしまう場合はFAIL(重大)。

## 【失敗時に記録する内容】

* アクセスできてしまった具体的なエンドポイント・画面、実際のレスポンス

* アプリケーションコードを修正しない。テストコードをその場で都合よく変更しない。失敗したテストをスキップしない。期待値を変更して成功扱いにしない。同じ失敗に対して場当たり的な再テストを繰り返さない。修正が必要な場合はP202以降に引き渡す。
