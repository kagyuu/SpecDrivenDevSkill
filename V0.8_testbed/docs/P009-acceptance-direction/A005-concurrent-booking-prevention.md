## 【目的】

* 実際に起動したサーバープロセスに対し、複数の同時HTTPリクエストで同一会議室・同一時間帯への予約作成を試みても、二重予約が発生しないことを実地検証する(`docs/P008-test-direction/T001〜T015` の単体・結合テストはプロセス内のテストクライアントで完結するため、実プロセス・実ネットワーク越しの検証として本テストを独立して行う。`docs/P001-requirement.md` 非機能要件「想定同時利用者数: 同時30接続程度」に対応)。

## 【参照テスト計画】

* `docs/P006-test-plan.md` 3章(負荷観点)

## 【対象モジュール】

* `server/` プロセス全体(実際に `uvicorn` で起動した状態)

## 【前提条件】全モジュールビルドが成功していること

* U001〜U005すべてが完了していること。`server/` を実際に起動しておくこと(テストプロセス内蔵のTestClientではなく、ネットワーク越しのHTTPリクエストで検証すること)。

## 【使用するテストデータ】

* 会議室1件、同一の会議室・同一時間帯(例: 15:00-16:00)を指定した予約リクエストを30並列で送信する

## 【事前準備】

* `uvicorn app.main:app --host 127.0.0.1 --port 8000` でサーバーを起動する
* 30個の異なる一般ユーザーアカウント(またはログイン済みセッション30個)を用意する。★FIXME★ 30アカウントの用意は事前準備コストが高いため、実装時は同一ユーザーの複数セッション、またはテスト専用の軽量アカウント生成スクリプトで代替してよい(検証したいのは「異なるリクエスト元からの同時書き込み」であり、予約者が同一ユーザーであること自体は本テストの本質に影響しない)。

## 【実行手順】

1. 30個のHTTPクライアント(スレッドまたは非同期タスク)から、同一会議室・同一時間帯(15:00-16:00)へのPOST /api/reservationsを可能な限り同時に送信する
2. 全レスポンスのステータスコードを集計する
3. SQLiteを直接クエリし、該当時間帯・該当会議室の予約が何件作成されたかを確認する

## 【実行コマンド】

* `cd server && python -m pytest tests/acceptance/test_concurrent_booking.py -v -s`(実プロセスに対してPythonの `concurrent.futures.ThreadPoolExecutor` または `httpx` の非同期クライアントで並列送信する)

## 【期待結果】

* 手順2: 201が1件、409が29件(またはリトライ処理を実装している場合はリトライ後に成功する別時間帯への振替は本テストの対象外とする、あくまで同一時間帯への直接的な同時実行の結果を見る)
* 手順3: 該当時間帯の予約は1件のみ
