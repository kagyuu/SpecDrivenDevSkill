# 【テストID】A009

> このテストは `docs/P006-test-plan.md` 4章で必須と定められた運用観点(再起動耐性)である。省略・NOT RUN化は原則として認められない(実行できない技術的理由が生じた場合は理由を明記のうえBLOCKEDとして記録すること)。

## 【目的】

* アプリケーションを停止・再起動しても正常に起動すること、既存データが保持されること、マイグレーション機構(`docs/P003-backend-spec.md` 3章)が冪等であることを実地で確認する。この観点は、テストごとに新しい一時DBを使う単体テスト・結合テスト(常に初回起動になる)では検出できない。

## 【参照テスト計画】

* `docs/P006-test-plan.md` 4章(運用観点、必須)

## 【対象モジュール】

* `server/app/db/migration.py`, `server/app/main.py`、永続SQLiteファイル

## 【前提条件】全モジュールビルドが成功していること

* U001〜U005すべてが完了していること

## 【使用するテストデータ】

* 永続ファイルパス(一時ファイルではない)のSQLiteデータベース。会議室・予約データを数件事前に投入する。

## 【事前準備】

* `DATABASE_PATH` を永続ファイル(例: `server/data/acceptance-test.db`)に設定してサーバーを1回目起動し、正常稼働(`GET /health` が200)を確認したうえで、会議室1件・予約1件を作成する

## 【実行手順】

1. サーバープロセスを正常停止する(SIGTERM等、異常終了ではなく正常終了)
2. 同じ `DATABASE_PATH` を指定して再度サーバーを起動する
3. 起動ログにマイグレーションエラーが出力されていないことを確認する
4. `GET /health` が200を返すことを確認する
5. 事前投入した会議室・予約データが `GET /api/rooms`, `GET /api/reservations` から引き続き取得できることを確認する
6. さらにもう一度(3回目)同じ手順で停止・起動を行い、2回目以降の再起動でも問題が起きないことを確認する(1回だけでなく複数回の再起動に耐えることを確認するため)

## 【実行コマンド】

* `cd server && DATABASE_PATH=./data/acceptance-test.db python -m pytest tests/acceptance/test_restart_resilience.py -v -s`(テスト内でサブプロセスとしてサーバーを起動・停止・再起動する)

## 【期待結果】

* 手順3: マイグレーション関連のエラーログが無い(特に `duplicate column name` 相当のエラーが出ないこと、`docs/P003-backend-spec.md` 3章の懸念点)
* 手順4: 200
* 手順5: 事前投入したデータがすべて取得できる
* 手順6: 3回目の起動も1・2回目と同様に問題なく完了する

## 【合否判定基準】

* 上記すべてを満たせばPASS。1回でも起動失敗・データ欠落・マイグレーションエラーが発生すればFAIL(`SKILL.md` の想定するP902/データ消失系の重大不具合に直結しうるため、重大度は高として扱う)。

## 【失敗時に記録する内容】

* 起動ログの全文、失敗した回(2回目/3回目)、エラーメッセージ
