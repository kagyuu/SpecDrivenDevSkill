# 結合テスト定義

## 目的

* 結合テスト定義を作成して、別の Agent に結合テストをさせる指示を取りまとめる。結合テストは、別の Agent に行わせるので、ここでは実行は行わない。
* 単体テスト、スプリントに閉じた結合テストの指示は、プログラム実装定義(`SKILL-06-impl-direction.md`)で行うので、ここでは指示しない
* ここでは、スプリントをまたぐ結合テスト、システムテスト(総合テスト)、受入テストの指示を行う

## インプット文書

* `docs/02-frontend-spec.md`
* `docs/03-backend-spec.md`
* `docs/04-impl-plan.md`
* `docs/05-test-plan.md`

## アウトプット文書

* `docs/07-test-direction.md` (目次 OKF形式)
* `docs/07-test-direction/T000-{test-name}.md` (000はテスト番号(実行順)、test-name はテスト名)

### アウトプットの記載内容

* 目次は OKF 形式(`SKILL.md` の「目次(OKF形式)について」参照)で作成して、各テストタスクへのリンクを保持する
* テスト指示は、テストケースごとに行い `docs/07-test-direction/T000-{test-name}.md` に分割して記載する
  * `TEMPLATE-07-test-direction.md` の構成に則る
* 対象とするテスト範囲
  * 複数モジュール間の連携テスト
  * 複数APIをまたぐ業務フローのテスト
  * 画面とAPIの接続テスト
  * 画面遷移を含むシナリオテスト
  * DB・Repository・Service・APIの組み合わせ確認
  * 認証・認可をまたぐ処理確認
  * エラーハンドリングの一連の確認
  * 外部APIやモックサービスを含む連携確認
  * システムテスト相当の主要シナリオ確認
  * 非機能テストのうち、実行可能な範囲の性能・負荷・セキュリティ観点確認
  * このSkillでは、純粋な関数単位のUnit Testや、単一クラス・単一コンポーネントだけのテスト指示、およびスプリントに閉じた結合テストは主対象にしない(それらは `docs/06-impl-direction.md` 側で指示済みの前提とする)。
* テスト前に必ず全モジュールをビルドするよう指示する
  * ビルド手順には以下を明記する。
    * ビルド対象
    * ビルドコマンド
    * 成功条件
    * 失敗時の記録方法
    * ビルド失敗時はテストへ進まないこと
* テスト失敗時にその場で修正しない
  * テスト担当LLMには、テスト失敗時にコードを修正させてはいけない。必ず以下を指示する。
    * アプリケーションコードを修正しない
    * テストコードをその場で都合よく変更しない
    * 失敗したテストをスキップしない
    * 期待値を変更して成功扱いにしない
    * 同じ失敗に対して場当たり的な再テストを繰り返さない
    * 失敗内容をテスト記録に残す
    * 次工程の修正フェーズに引き渡す
* テスト記録を必ず残させる
  * 記録先　`docs/test-records/YYYYMMDD-HHMM-test-record.md`
  * 記録形式は、各テストタスクごとに以下を残す。

```markdown
## T000: テスト名

- 実行日時:
- 実行者:
- 対象ブランチ/コミット:
- 参照したテスト指示:
- 実行環境:
- 事前ビルド結果:
- 実行コマンド:
- 結果: PASS / FAIL / BLOCKED / NOT RUN
- 期待結果:
- 実際の結果:
- 失敗ログ抜粋:
- 再現手順:
- 影響がありそうなモジュール:
- 次工程への申し送り:
```

* テストタスクを小さくする
  * 1つのテストタスクは、原則として以下の範囲に収める。
    * 1つの業務シナリオ
    * 1つの画面/API連携
    * 1つの主要API連鎖
    * 1つのエラー系シナリオ
    * 1つの非機能観点
  * 避けること
    * 「全画面をテストする」
    * 「全APIを結合テストする」
    * 「正常系と異常系を全部まとめて確認する」
    * 「性能・セキュリティ・認証・業務フローを一度に確認する」
    * 「失敗したら直して成功するまで回す」
* 低性能LLM向けに具体的に書く
  * 各テストタスクには、少なくとも以下を含める。
    * 目的
    * 対象モジュール
    * 前提条件
    * 使用するテストデータ
    * 事前準備
    * 実行手順
    * 実行コマンド
    * 期待結果
    * 合否判定基準
    * 失敗時に記録する内容
    * 修正禁止事項
    * 次タスクへ進む条件
    * テスト担当LLMへそのまま渡せる指示文
* テストタスクが完了したら(PASS/FAIL/BLOCKEDいずれの結果であっても記録が残った時点で)、テスト担当Agentは `docs/07-test-direction.md` の該当テスト行のチェックボックスを `[x]` に更新する。全テストが `[x]` になるまでフェーズ7は完了しない。ただしFAIL/BLOCKEDが残っている場合は、フェーズ8(修正)への引き渡しが必要である旨を目次に明記する。

### アウトプットを参照する文書

アウトプットの記載内容は、次の文書を作成できる程度に具体的であること

* テスト担当LLMが、テスト指示のみを参照してテストを行う。

## 動作

* 共通指示に加えて、上記アウトプット記載内容に定めた事項に従う。
