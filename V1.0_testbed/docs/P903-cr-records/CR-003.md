# CR-003 — 予約データを外部の基幹システムへ自動連携してほしい 対処記録

変更要求: [`docs/P901-cr-direction/CR-003.md`](../P901-cr-direction/CR-003.md)

## 却下理由(P901が起票時点で記載)

* **却下**。`SKILL-P901-cr-create.md`「起票の時点で却下が決まっている場合」の規定にもとづき、P901がこの却下理由をこのファイルに直接記録する(通常このファイルはP903が作成するが、却下によりP902以降に到達しないための例外)。
* 却下の理由:
  1. 連携先である外部基幹システムのAPI仕様(エンドポイント、認証方式、データ形式、レート制限)が一切示されておらず、`docs/P001-requirement.md`「システムの前提」にも外部システム連携の記載が無い。この情報は本システム側の設計・実装からは導出できず、**連携先を管理する組織(総務部・情シス)から提供を受ける以外に入手経路が無い**。仕様が確定しない状態では、P003(システム詳細設計)以降を実行できない。
  2. 外部システム障害時の挙動(タイムアウト値、リトライ回数、再送の運用手順)は、連携先のSLAと運用体制に依存する。これも本システム単独では決定できない。
* **本CRは、対処案そのものを本Skillが提示できない性質のものではない**(仕様が提供されれば設計・実装は可能である)。したがって却下は「実現不能」を意味せず、「**前提情報が揃っていないため、現時点ではCRとして着手できない**」ことを意味する。
* 次のアクション(人間側): 連携先基幹システムのAPI仕様書と、障害時の運用方針(再送の要否・許容遅延)を入手したうえで、新しいCR番号で改めて起票すること。その際、`docs/P001-requirement.md`「システムの前提」に外部システム連携を追加する必要があるため、P902(要件定義更新)を伴う変更になる。
* この却下判断を覆す新たな要望が来た場合は、新しいCR番号で改めて起票すること(本CRを再利用しない、`SKILL-P901-cr-create.md` の原則どおり)。

## 対処内容

* 却下のため該当なし。
