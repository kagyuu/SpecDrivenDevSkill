### マイグレーション方式の確認(「データモデル変更」に該当するため)

* `docs/P003-backend-spec.md` に記載されている適用方式: 差分適用方式(`schema_migrations` テーブルでバージョン管理、`server/app/db/migrate.py`)。
* その方式は冪等か: **冪等である**。新しいマイグレーションファイル(`004_add_reservation_internal_memo.sql`)を追加するだけであり、既存の001〜003は再実行されない。`ALTER TABLE reservations ADD COLUMN internal_memo TEXT`(条件付き構文を持たないDDL)を追加するが、バージョン管理テーブルにより本マイグレーション自体が2回以上実行されることはないため、`duplicate column name` エラーは発生しない構造になっている。
* 冪等でない場合、冪等化を本CRの対応範囲に含めるか: 該当なし(既に冪等な方式のため追加対応不要)。ただし、`docs/P006-test-plan.md`・CRの「期待する振る舞い」の要求どおり、実際に初期化処理を2回連続で実行して確認する(P101〜P104実施時、下記「対処内容」参照)。
