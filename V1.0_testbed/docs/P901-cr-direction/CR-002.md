# CR-002 — 会議室予約システムに全社チャット機能を追加してほしい

## 起票日

2026-08-11

## 起票者

* 利用者からのフィードバック(詳細不明。コーディネーター経由での要望伝達のため、依頼者個人・チケット番号は特定できていない)★FIXME★ 起票者の具体的な氏名・チケット番号が判明した場合は追記すること。

## 背景・課題

* 会議室予約システムの利用者から、「予約した会議に関する連絡を、このシステム上でチャットのように行いたい」「そのついでに全社向けの雑談・連絡用チャット機能も欲しい」という趣旨の要望が寄せられた。

## 変更要求の内容

* 会議室予約システムに、全社員が利用できるチャット機能(メッセージ送受信、チャンネル、既読管理等を想定)を新規に追加してほしいという要望。
* 対応する既存の仕様箇所: なし。`docs/P001-requirement.md` は会議室予約(検索・予約・管理)を目的とするシステムとして定義されており、チャット・メッセージング機能は要件・画面(S01〜S07)・データモデル・APIのいずれにも含まれていない。

## 期待する振る舞い

* (却下のため、期待する振る舞いの整理は行わない。理由は「優先度の判断理由」および `docs/P903-cr-records/CR-002.md` を参照。)

## 影響が想定される範囲

* 画面: 新規のチャットUI一式(既存のS01〜S07のいずれにも該当しない)。
* API: 新規のメッセージ送受信・チャンネル管理API一式(既存の17本のAPIのいずれにも該当しない)。
* データモデル: メッセージ・チャンネル・既読状態等の新規テーブル一式(既存の`users`/`rooms`/`sessions`/`reservations`/`reservation_participants`のいずれにも該当しない)。
* 関連ADR: なし。
* 既存ADRに抵触する要望ではない(新規の独立した機能追加のため、既存決定を覆すものではない)。ただし後述のとおり、システムの目的そのものの範囲外であるため却下する。
