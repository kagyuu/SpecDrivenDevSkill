# 矛盾点の影響分析結果

> 本書は `spec-driven-dev` Skill フェーズP011の成果物。`docs/P010-design-review.md` 1回目実行で列挙された矛盾点の影響分析を行う。修正そのものはP012で行う。

## 矛盾点 #1

- 概要: `docs/P007-impl-direction.md`「コード格納先」節が、`docs/ADR.md` 未作成の時点でADR-001/002を確定番号のように記載し、かつ技術スタック名(React+TypeScript+Vite、Python+FastAPI)を目次にハードコードしている。
- 修正すべき文書と箇所: `docs/P007-impl-direction.md` の「コード格納先」節。
- どちらの記述を正とすべきか(判断とその理由): `SKILL.md`(各フェーズ共通指示「ADR番号の暫定参照について」)および `SKILL-P007-impl-direction.md`(ハードコード禁止の指示)が上位ルールであり、`docs/P007-impl-direction.md` 側を両ルールに合わせて修正する。
- 波及して確認・修正が必要になる他の文書・箇所: `docs/P007-impl-direction/U001〜U004-*.md` 内で同様の技術名ハードコードが無いか確認する(確認の結果、各スプリントファイルは実装内容の詳細説明中でのみ技術名(React/FastAPI/bcrypt等)に言及しており、これは `SKILL-P007-impl-direction.md` が明示的に許容する「実装内容の詳細な説明の中で技術名に言及すること自体は問題ない」の範囲内であるため、修正不要と判断した)。
- 修正の優先度: 中

## 矛盾点 #2

- 概要: `docs/P003-backend-spec.md` の暫定ADR番号(ADR-002=sqlite3直接アクセス、ADR-003=bcrypt)と、`docs/P007-impl-direction.md` の想定(ADR-002=バックエンド技術FastAPI)が食い違っている。また、バックエンド技術(FastAPI)選定自体とセッション管理方式(§2.1)にADR番号(暫定含む)が付与されていない。
- 修正すべき文書と箇所: `docs/P003-backend-spec.md` §0(使用技術)・§2.1(セッションの内部実現)。矛盾点#1の修正と合わせて `docs/P007-impl-direction.md` 側の番号とも整合させる。
- どちらの記述を正とすべきか(判断とその理由): どちらか一方を優先するのではなく、両文書が共通で参照できるADR番号割り当てを新たに整理する。決定の独立性(P021の粒度基準「独立に覆される可能性がある決定は別々のADRに分ける」)にもとづき、フロントエンド技術・バックエンド技術・データアクセス方式(ORM有無)・パスワードハッシュ方式・セッション管理方式の5つを、それぞれ独立に見直されうる決定として個別のADR番号(暫定)に割り当てる。
- 波及して確認・修正が必要になる他の文書・箇所: `docs/P004-traceability-matrix.md`・`docs/P005-impl-plan.md`・`docs/P006-test-plan.md`・`docs/P008-test-direction.md`・`docs/P009-acceptance-direction.md` にはADR番号への直接参照が無いことを確認済み(該当なし、修正不要)。
- 修正の優先度: 中

## 補足

* いずれの矛盾点も、既存のADR(まだ存在しない)を覆す修正ではないため、P021への申し送り事項はない。P021初回実行時に、本書で整理した暫定番号(ADR-001〜005見込み)がそのまま確定番号になることを想定する。
