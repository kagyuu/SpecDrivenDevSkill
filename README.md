# Spec-Driven Dev Skill

Claude Code に、日本のシステム開発で標準的な**ウォーターフォール/V字モデル**の手順を踏ませて開発を行わせるための Skill(指示書一式)。

あいまいな要求からいきなりコードを書かせるのではなく、要件を9つのフェーズで段階的に具体化し、最後に実装指示書・テスト指示書を作ってから初めて実装・テストに進ませる。テストで見つかった不具合の修正も、いきなりコードを触らせず、まず修正計画を作らせてから着手させる。

## このリポジトリの構成(バージョン履歴)

このリポジトリは、Skill そのものを Claude Code とやり取りしながら育てていった履歴を兼ねているため、通常のプロジェクトとは違い、バージョンごとのフォルダをそのまま並べる変則的な構成にしている。

```
V0.1/   最初のドラフト
V0.2/   整合性・実行可能性・記述一貫性の観点でレビューし、不備を修正した版
V0.3/   (以降、改訂のたびに Vx.y フォルダが増えていく)
```

* 各 `Vx.y/` フォルダは、その時点での Skill 一式(`SKILL.md` + `SKILL-01〜09-*.md` + `TEMPLATE-*.md`)をまるごと収めたスナップショット。
* 実際に使うときは、**最も新しいバージョンのフォルダ**を使うこと。
* バージョンごとに何を直したかは、そのバージョンのフォルダにある `review-report.md`(存在する場合)に記載している。

## Skill の中身(9フェーズ構成)

各フェーズは、対象プロジェクトの `docs/` 配下に Markdown 成果物を1つずつ作っていく。**1回の実行につき1フェーズだけ**進め、そこで止めて人間のレビューを待つ。前のフェーズの内容が正しいことを前提に次のフェーズを作るため、レビューを飛ばすとこの手順の意味がなくなる。

| フェーズ | フェーズ名 | 生成する主なドキュメント | 性質 |
| --- | --- | --- | --- |
| 1 | システム要件定義 | `docs/01-requirement.md` | 人間と対話しながら作る計画書 |
| 2 | ユーザインタフェース設計 | `docs/02-frontend-spec.md` | 同上 |
| 3 | システム詳細設計 | `docs/03-backend-spec.md` | 同上 |
| 4 | 実装計画 | `docs/04-impl-plan.md` | 同上 |
| 5 | テスト計画 | `docs/05-test-plan.md` | 同上 |
| 6 | プログラム実装定義 | `docs/06-impl-direction.md` + `06-impl-direction/U000-*.md` | 実装担当Agent向けの実行指示書 |
| 7 | 結合テスト定義 | `docs/07-test-direction.md` + `07-test-direction/T000-*.md` | テスト担当Agent向けの実行指示書 |
| 8 | 修正 | `docs/08-fix-plan.md` + `08-fix-plan/F000-*.md` | 修正担当Agent向けの実行指示書 |
| 9 | 納品物作成 | `docs/09-deliver.md` | 納品担当Agent向けの実行指示書 |

このSkill自体はソースコードやテストの実行は行わない。フェーズ6以降で生成される実装指示・テスト指示・修正指示という「Markdown」を、別のClaude Codeセッション(実装担当・テスト担当・修正担当のAgent)に渡して初めて、コードが書かれたりテストが実行されたりする。

## 使い方(Claude Codeへの導入方法)

1. 使いたい**最新バージョンのフォルダの中身**(`SKILL.md` `SKILL-01〜09-*.md` `TEMPLATE-*.md`)を、開発対象プロジェクトの Skill 用フォルダ(例: `.claude/skills/spec-driven-dev/`)にそのままコピーする。
2. 対象プロジェクトで Claude Code を起動し、この Skill を使って開発を進めるよう依頼する。
3. `SKILL.md` の「ステップ0」により、対象プロジェクトの `docs/` の状態(どのフェーズまで完了しているか)から、実行するフェーズが自動的に仮確定される。仮確定されたフェーズでよければそのまま Enter、別のフェーズを指定したい場合は番号を入力する。
4. 1フェーズ実行したら、生成された `docs/0X-*.md` の内容をレビューする。問題なければ次に Claude Code を起動したときに次のフェーズへ進む(`docs/.inprogress` に次フェーズ番号が記録される)。
5. フェーズ6(実装)・7(結合テスト)・8(修正)で生成される指示書は、実装・テスト・修正それぞれの担当として動く別のClaude Codeセッションに読み込ませて実行させる。この Skill 自身はコードを書いたりテストを実行したりしない。
6. フェーズ9まで完了すると `docs/.inprogress` が削除され、`docs/09-deliver.md` に納品判定がまとまる。

## 現在のステータス

* 現時点の最新版: `V0.2/`
* `V0.1` → `V0.2` では、開発体系の整合性(フェーズ間のファイル参照の食い違いなど)・実行可能性(未定義用語や壊れたテンプレートなど)・記述の一貫性(見出し構成のばらつきなど)の3観点でレビューし、不備を修正した。詳細は `V0.2/review-report.md` を参照。
