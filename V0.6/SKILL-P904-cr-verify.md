# 変更要求の反映確認

## 目的

* P903で行った修正が、`docs/CR.md` に記載された変更要求の内容をすべて満たしているかを確認する。
* 満たしていることを確認できたCRは、状態および対処内容を追記したうえで `docs/cr-records/` に退避する。

## インプット文書

* `docs/CR.md`
* P903で更新された `docs/P002-frontend-spec.md` 〜 `docs/P302-deliver.md`、ソースコード、テスト記録

## アウトプット文書

* `docs/cr-records/CR-{番号}.md` (対応が完了したCR)
* `docs/CR.md` (対応が完了したCRの反映。反映方法は下記「アウトプットの記載内容」の手順に従う)

### アウトプットの記載内容

* CRごとに、「期待する振る舞い」がテスト(P008/P009)で確認できているかを確認する。確認できていなければ、状態を `対応中` のままにし、不足している対応を明記して人間に報告する。
* 確認できたCRは、`TEMPLATE-CR.md` の「対処内容」欄に、実際に変更したフェーズ・ドキュメント・コードを追記し、状態を `完了` にしたうえで、CR本文全体を `docs/cr-records/CR-{番号}.md` にコピーする。
* `docs/CR.md` から `完了` になったCRを反映する手順は、**そのプロジェクトの `docs/CR.md` に既に完了済みCRの記載が存在するかどうか**で決まる。「残す」か「削除する」かの二者択一で判断してはならない(実際の運用では、その中間にあたる記法が自然に生まれるため)。

* **既に完了済みCRの記載が `docs/CR.md` に存在する場合(2件目以降のCR処理)**: 直近の完了済みCRが実際にどう記載されているかを `docs/CR.md` の現物で確認し、**その記載形式をそのまま複製する**。自分の解釈で「残す/削除する」のどちらかに寄せ直してはならない。確認すべきなのは次の3点である。
  * 完了したCRの行が「CR 一覧」の表に残っているか、表からは除かれているか。
  * 表とは別に、完了済みCRへの参照(`docs/cr-records/` へのリンク一覧など)が置かれているか。置かれている場合、その見出し・並び順・1行の書式(リンクの書き方、タイトル、完了日の有無など)。
  * CR本文(`## CR-{番号}` 以降の節)が `docs/CR.md` に残っているか、`docs/cr-records/` への退避に伴って削除されているか。

* **完了済みCRの記載がまだ存在しない場合(そのプロジェクトで初めてCRを完了させる場合)**: 次の形式を既定とする。この形式は、`docs/CR.md` を「いま対応すべきCRの一覧」として読めるよう保ちつつ、完了したCRも辿れるようにするためのものである。
  1. CR本文(`## CR-{番号}` 以降の節)は `docs/CR.md` から削除し、`docs/cr-records/CR-{番号}.md` に退避する(本文を二重に持たない)。
  2. 「CR 一覧」の表からは、完了したCRの行を除く。表に未対応・対応中のCRが1件も残らない場合は、`| (現在、未対応・対応中のCRはありません) | | | |` のようなプレースホルダ行を置き、表そのものは残す。
  3. 表の直後に「対応完了済みのCRは `docs/cr-records/` を参照。」という一文と、完了したCRへのリンクを1件1行で並べた箇条書きを置く。書式は次のとおりとし、完了順に追記していく。

```markdown
対応完了済みのCRは `docs/cr-records/` を参照。

* [`docs/cr-records/CR-001.md`](./cr-records/CR-001.md) — (CRのタイトル)(完了、YYYY-MM-DD)
```
