# testbed.md — spec-driven-dev Skill 実地検証(テストヘッド)

## これは何か

`spec-driven-dev` Skill(V0.2)を、実際のターゲットプロジェクトに対して **フェーズ1から9まで通しで自動実行** し、Skillの指示書自体に矛盾や実行不能な箇所がないかを実地検証するための記録。

`V0.2/review-report.md` の「残課題」5番に記載されていた

> End-to-Endの実地検証は未実施(...)2026-07-29時点でユーザーからは「いずれ行うので今は不要」との回答済み

に対応する、その「いずれ」の実施記録。

## テストヘッドアプリケーション

**会議室予約システム** — 社内の会議室予約を一元管理するWebアプリ。画面遷移・CRUD API・権限制御・非機能要件など、9フェーズを一通り試せる規模で、かつ複雑になりすぎないものとして選定。

* 要求仕様: [`docs/01-requirement.md`](./docs/01-requirement.md)(フェーズ1成果物、確定済み)
* 技術スタック: フロントエンド React 18 + TypeScript + Vite / バックエンド Python + FastAPI / データストア SQLite

## 検証範囲(今回のスコープ)

ユーザー承認のスコープ: **フルパイプライン**。

* フェーズ2〜9をSkillの指示(`.claude/skills/spec-driven-dev/SKILL.md` 以下)に従って通しで自動実行する。
* フェーズ6(実装定義)以降は、生成された指示書(`U000-*.md` / `T000-*.md` / `F000-*.md`)を、Skillが本来別セッションに委ねる実装・テスト・修正担当Agentの役も兼ねて実際に実行する。つまり実際にコード(FastAPI + SQLite バックエンド、フロントエンド)を書き、テストを実際に走らせ、不具合が出れば修正サイクルも回す。
* 通常運用の「1フェーズごとに人間レビューで停止」というルールは、無人の自動検証という性質上、このテストヘッドの実行に限り自己レビュー(生成物がそのフェーズの完了基準を満たしているかをAgent自身が判定)に置き換えて連続実行する。SKILL自体の当該ルールを変更するものではない。

## 発見した不備への対応方針

**レポートのみ作成**。V0.2のSkillファイル自体は変更しない。矛盾・実行不能な指示など見つかった不備は本テストヘッド配下の `e2e-validation-report.md` にまとめる。修正が必要と判断した場合は、ユーザー確認の上で `CLAUDE.md` のルールに従い改めて `V0.3/` フォルダを作成して対応する(このテストヘッド実行の中では行わない)。
