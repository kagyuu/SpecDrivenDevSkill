# 【テストID】A010 — セキュリティの横断確認

## 【目的】

* P001の非機能要件(パスワードのハッシュ化、権限チェック、HTTPS前提)に対応するアプリケーション側の実装が、実際に守られていることを確認する。

## 【参照テスト計画】

* `docs/P006-test-plan.md` 3.2 V-N-03 / V-N-04 / V-N-05 / V-N-06、4.3
* 仕様: `docs/P001-requirement.md` 非機能要件(セキュリティ)、`docs/P003-backend-spec.md` 4.3・4.4・8

## 【対象モジュール】

* `security.py`、`auth.py`、`errors.py`、`logging_middleware.py`、全ハンドラ

## 【前提条件】全モジュールビルドが成功していること

* 第2章のビルドコマンドが終了コード0で完了していること。

## 【使用するテストデータ】

* 基準データセット。パスワード `Passw0rd!23`。

## 【事前準備】

1. DBファイルを削除し、基準データセットを投入してサーバーを起動する。
2. サーバーの標準出力をファイルに退避して後で検査できるようにする。

## 【実行手順】

1. DBの `users.password_hash` を全件確認する。
2. 全APIのレスポンス本文を横断的に検査し、`password` を含むキーが存在しないことを確認する。
3. ログイン応答の `Set-Cookie` 属性を確認する。
4. 一般ユーザーのセッションで管理者専用API 8本を呼ぶ(A003と重複するが、セキュリティ観点として再確認する)。
5. 意図的に 500 を発生させる(存在しないDBパスを指定した別プロセスを起動する、または内部例外を誘発する)。応答本文を確認する。
6. 退避したログを検査し、パスワード・`sid` の値・セッションIDが含まれていないことを確認する。
7. `GET /api/users?scope=attendee_candidates` の応答に `role` が含まれないことを確認する。

## 【実行コマンド】

* `cd server && python3 -m unittest tests.acceptance.test_a010_security -v`

## 【期待結果】

* 手順1: 全件が `scrypt$` で始まる文字列で、平文パスワードと一致しない。同じパスワードでもユーザーごとに値が異なる。
* 手順2: `password` / `password_hash` を含むキーが1つもない。
* 手順3: `HttpOnly` `SameSite=Lax` `Secure` `Path=/` がすべて付与されている。
* 手順4: 8本すべて 403。
* 手順5: 応答本文に**スタックトレース・SQL文・ファイルパスが含まれない**(`{"error":{"code":"INTERNAL_ERROR", ...}}` のみ)。
* 手順6: ログにパスワード・`sid` の値が含まれない。5xxのログには `stack` が含まれる(サーバー側には残す)。
* 手順7: `role` が含まれない。

## 【合否判定基準】

* 上記すべてを満たせばPASS。手順1・2・5・6のいずれかに違反があればFAIL(重大度「高」)。
* なお、TLS(HTTPS)そのものはアプリケーションの外側(リバースプロキシ)の責務であり、本テストの対象外である(`docs/P003-backend-spec.md` 8章の委譲による。実際の確認は `docs/P302-deliver.md` で行う)。
