# 【テストID】A008 — カレンダー表示の性能

## 【目的】

* P001の非機能要件「カレンダー画面の表示は3秒以内」を、想定規模(会議室10室 × 1週間)のデータで満たすことを確認する。

## 【参照テスト計画】

* `docs/P006-test-plan.md` 3.2 V-N-01、4.3
* 仕様: `docs/P001-requirement.md` 非機能要件(性能)、`docs/P003-backend-spec.md` 8(性能行)、3.4(インデックス)

## 【対象モジュール】

* `handlers/reservation_handlers.py`(API-12)、`repositories/reservations_repo.py`、`client/src/views/s02-calendar.js`、`client/src/lib/grid.js`

## 【前提条件】全モジュールビルドが成功していること

* 第2章のビルドコマンドが終了コード0で完了していること。

## 【使用するテストデータ】

* 会議室 **10室**(すべて有効)、ユーザー10名、1週間分の予約 **約200件**(1室あたり1日3〜4件、平日5日分)を投入する。

## 【事前準備】

1. DBファイルを削除し、上記のデータを生成して投入する(生成スクリプトを用いてよい)。
2. サーバーを起動し、`user001` でログインする。
3. 計測前に1回ウォームアップのリクエストを送る(初回のインポート・接続確立の影響を除くため)。

## 【実行手順】

1. `GET /api/rooms` の応答時間を5回計測する。
2. `GET /api/reservations?date_from={週初}&date_to={週末}` の応答時間を5回計測する。
3. S02の描画関数を、上記2つの応答を入力として実行し、所要時間を5回計測する。
4. 手順1〜3の合計(=画面表示完了までの目安)を算出する。
5. サーバーログの `duration_ms` を確認する。
6. 発行されたSQLの回数(またはRepositoryの呼び出し回数)を確認する。

## 【実行コマンド】

* `cd server && python3 -m unittest tests.acceptance.test_a008_calendar_performance -v`

## 【期待結果】

* 手順2: 5回の**中央値が1秒以内**。
* 手順4: 5回の**中央値が3秒以内**(P001の非機能要件)。
* 手順6: API-12の1リクエストにつき、予約取得のSQLが**1回だけ**発行される(N+1になっていない)。

## 【合否判定基準】

* 手順2・4・6のすべてを満たせばPASS。
* 3秒を超えた場合は、計測値・件数・実行環境(CPU・メモリ)を記録したうえでFAILとする。★FIXME★ サンドボックス環境の性能は本番環境と異なるため、FAIL時は「環境依存の可能性あり」を併記すること。
