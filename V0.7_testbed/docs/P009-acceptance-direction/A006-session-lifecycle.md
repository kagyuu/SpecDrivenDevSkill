# 【テストID】A006 — 認証セッションのライフサイクル

## 【目的】

* セッションの発行・維持・失効(無操作タイムアウト、絶対期限、ログアウト、ユーザー無効化、権限変更)が、画面の挙動まで含めて仕様どおりであることを確認する。

## 【参照テスト計画】

* `docs/P006-test-plan.md` 3.1 V-F-04、3.2 V-N-04、4.3
* 仕様: `docs/P002-frontend-spec.md` 2.3・5.4、`docs/P003-backend-spec.md` 2.2・4.3

## 【対象モジュール】

* `auth.py`、`services/auth_service.py`、`repositories/sessions_repo.py`、`services/user_service.py`、`client/src/lib/api.js`

## 【前提条件】全モジュールビルドが成功していること

* 第2章のビルドコマンドが終了コード0で完了していること。

## 【使用するテストデータ】

* `user001`、`admin001`。

## 【事前準備】

1. DBファイルを削除し、基準データセットを投入してサーバーを起動する。

## 【実行手順】

1. `user001` でログインし、`Set-Cookie` の属性を確認する。
2. 30分相当の時間差を挟んで(`last_accessed_at` を意図的に巻き戻して)アクセスし、セッションが維持されることを確認する。
3. `last_accessed_at` を9時間前に書き換えてアクセスする。
4. 再ログインし、`expires_at` を過去に書き換えてアクセスする。
5. 再ログインし、S02を開いた状態でセッションを削除してから画面操作を行う。
6. 再ログインし、`admin001` から `user001` を無効化した後にアクセスする。
7. 再ログイン後(`user001` を有効に戻す)、`admin001` が `user001` の `role` を `admin` に変更した後にアクセスする。
8. ログアウトしてから同じCookieでアクセスする。

## 【実行コマンド】

* `cd server && python3 -m unittest tests.acceptance.test_a006_session_lifecycle -v`
* `cd client && node --test tests/acceptance/test_a006_session_ui.js`

## 【期待結果】

* 手順1: `HttpOnly` `SameSite=Lax` `Secure` `Path=/` がすべて付与されている。
* 手順2: 200(スライディング期限で維持される)。
* 手順3: 401 `UNAUTHENTICATED`。
* 手順4: 401(絶対期限)。
* 手順5: 画面が `#/login` へ遷移し、「セッションの有効期限が切れました。再度ログインしてください。」が表示される。
* 手順6: 401(無効化でセッションが削除される)。
* 手順7: 401(権限変更でセッションが削除される)。
* 手順8: 401。

## 【合否判定基準】

* 上記すべてが一致すればPASS。
