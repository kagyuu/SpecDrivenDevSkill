# 【テストID】A012 — 運用者視点の受け入れシナリオ

## 【目的】

* 運用者(総務・情シス)の視点で、初期セットアップ・日常運用・障害復旧の最低限の操作が成立することを確認する。

## 【参照テスト計画】

* `docs/P006-test-plan.md` 4.4(受け入れテスト)、3.2 V-N-07(ログ監視)、V-N-08
* 仕様: `docs/P001-requirement.md` 非機能要件(可用性・ログ出力先と監視方法)、`docs/P003-backend-spec.md` 3.6・4.4・8

## 【対象モジュール】

* `config.py`、`db.py`(シード)、`logging_middleware.py`、起動処理

## 【前提条件】全モジュールビルドが成功していること

* 第2章のビルドコマンドが終了コード0で完了していること。

## 【使用するテストデータ】

* 環境変数 `INITIAL_ADMIN_ID=ops0001` / `INITIAL_ADMIN_PASSWORD=OpsPassw0rd!` を明示的に指定する。

## 【事前準備】

1. DBファイルを削除する(まっさらな状態からの初期セットアップを再現する)。
2. サーバーの標準出力をファイルに退避する。

## 【実行手順】

1. 環境変数を指定してサーバーを起動する。
2. 初期管理者 `ops0001` でログインできることを確認する。
3. 管理者として会議室を1件、ユーザーを1件登録する(初期セットアップ相当)。
4. 一般ユーザーで予約を1件作る。
5. 退避したログを確認する(1リクエスト1行のJSONか、必要項目が揃っているか)。
6. 意図的に 404 と 403 を発生させ、ログに `error_code` が記録されることを確認する。
7. サーバーを停止し、再起動して、手順3・4のデータが残っていることを確認する。
8. `DB_PATH` に書き込めないパスを指定して起動し、**起動が失敗すること**(中途半端に起動しないこと)を確認する。

## 【実行コマンド】

* `cd server && python3 -m unittest tests.acceptance.test_a012_operator_acceptance -v`

## 【期待結果】

* 手順1: 起動に成功し、`ops0001` が作成される(既定値ではなく環境変数の値が使われる)。
* 手順2: 200。
* 手順5: 各行がJSONとしてパースでき、`ts` `level` `method` `path` `status` `duration_ms` `user_id` を含む。パスワード・`sid` を含まない。
* 手順6: `error_code` に `NOT_FOUND` / `FORBIDDEN` が記録される。
* 手順7: データが保持されている。
* 手順8: プロセスが異常終了し、リクエストを受け付けない。
* **運用の未確定事項**(記録のみ。このテストの合否には含めない): TLS終端、プロセス監視・自動再起動、ログの集約先(CloudWatch Logs等)への転送は `docs/P302-deliver.md` に委譲されている(`docs/P003-backend-spec.md` 8章)。本テストではアプリケーション側の前提が満たされていることのみを確認する。
