# 【テストID】T006 — 会議室名の一意性と無効化後の再登録

## 【目的】

* 有効な会議室のなかでのみ名前が一意であること(部分ユニークインデックス)を、DB制約とService層の409応答の両面で確認する。

## 【参照テスト計画】

* `docs/P006-test-plan.md` 4.2(Sprint 2)、3.1 V-F-08
* 仕様: `docs/P002-frontend-spec.md` 3.6・5.5(409 `DUPLICATE_KEY`)、`docs/P003-backend-spec.md` 3.4・6.2

## 【対象モジュール】

* `services/room_service.py`、`repositories/rooms_repo.py`、`migrations/002-rooms.sql`

## 【前提条件】対象スプリントの全モジュールビルドが成功していること

* Sprint 2 の単体テストが全件PASSしていること。

## 【使用するテストデータ】

* 会議室名 `会議室A`(重複させる対象)、`会議室B`。

## 【事前準備】

1. DBファイルを削除し、サーバーを起動し、ユーザーを投入して `admin001` でログインする。

## 【実行手順】

1. `会議室A` を登録する。
2. もう一度 `会議室A` を登録する。
3. `会議室B` を登録し、`PUT` で名前を `会議室A` に変更しようとする。
4. 手順1の会議室Aを `DELETE`(無効化)する。
5. 再度 `会議室A` を登録する。
6. `GET /api/rooms?include_inactive=true` を呼ぶ。

## 【実行コマンド】

* `cd server && python3 -m unittest tests.integration.test_t006_room_name_uniqueness -v`

## 【期待結果】

* 手順2: 409 `DUPLICATE_KEY`、メッセージ「同じ名前の会議室がすでに登録されています。」。
* 手順3: 409 `DUPLICATE_KEY`。
* 手順4: 204。
* 手順5: **201(成功する)**。無効化済みの同名会議室があっても登録できる。
* 手順6: `会議室A` が2件(1件は `is_active=0`、1件は `1`)返る。

## 【合否判定基準】

* 上記すべてが一致すればPASS。手順5が409になる場合は、`rooms.name` に全行ユニーク制約が付いている可能性が高い(FAIL)。
