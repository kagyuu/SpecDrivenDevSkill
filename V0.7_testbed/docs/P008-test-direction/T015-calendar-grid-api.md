# 【テストID】T015 — S02カレンダーと予約APIの接続

## 【目的】

* S02が `GET /api/rooms` と `GET /api/reservations` の結果からグリッドを正しく構築し、セルの表示内容・クリック時の遷移が仕様どおりであることを確認する。

## 【参照テスト計画】

* `docs/P006-test-plan.md` 4.2(Sprint 4)、3.1 V-F-10 / V-F-12
* 仕様: `docs/P002-frontend-spec.md` 3.2・4

## 【対象モジュール】

* `client/src/views/s02-calendar.js`、`client/src/lib/grid.js`、`client/src/lib/datetime.js`、`client/src/lib/api.js`

## 【前提条件】対象スプリントの全モジュールビルドが成功していること

* Sprint 4 のクライアント単体テストが全件PASSしていること。サーバー側 Sprint 1〜3 が動作すること。

## 【使用するテストデータ】

* 会議室A・B(有効)、会議室C(無効)。予約: 「本日+1日」会議室A 10:00-11:00(`user001`、件名「定例会議」)。

## 【事前準備】

1. DBファイルを削除し、サーバーを起動し、基準データセットを投入する。
2. `user001` でログインする。

## 【実行手順】

1. S02を描画し、APIが `GET /api/rooms` と `GET /api/reservations` を**それぞれ1回ずつ**呼ぶことを確認する。
2. 会議室の列数と、無効な会議室Cが列に現れないことを確認する。
3. 「本日+1日」の 10:00 / 10:30 / 11:00 のセルの内容を確認する。
4. 予約済みセルに参加予定人数が表示されていないことを確認する。
5. 会議室フィルタで会議室Aだけを選択し、APIが再度呼ばれないことを確認する。
6. 「翌週」ボタンを押し、`date_from` が7日進んだ状態でAPIが呼ばれることを確認する。
7. 空きセル(「本日+1日」会議室B 14:00)をクリックする。
8. 予約済みセル(手順3のセル)をクリックする。
9. 過去日(本日-1日)の空きセルをクリックする。

## 【実行コマンド】

* `cd client && node --test tests/integration/test_t015_calendar_grid_api.js`

## 【期待結果】

* 手順1: 各1回。
* 手順2: 有効な会議室2列のみ。
* 手順3: 10:00 と 10:30 に「山田 太郎 / 定例会議」が表示され、**11:00 は空き**。
* 手順4: 参加予定人数の文字列がセルに含まれない。
* 手順5: 列が1つに減り、APIの追加呼び出しが0回。
* 手順6: `date_from` が+7日で呼ばれる。
* 手順7: 遷移先が `#/reservations/new?room_id={B}&date={本日+1日}&start=14:00`(終了は開始+30分として扱われる)。
* 手順8: 遷移先が `#/reservations/{reservation_id}`。
* 手順9: 遷移せず「過去の日付には予約できません。」が表示される。

## 【合否判定基準】

* 上記すべてが一致すればPASS。手順3で 11:00 が予約済み表示になる場合はFAIL(終了スロットを占有している)。
