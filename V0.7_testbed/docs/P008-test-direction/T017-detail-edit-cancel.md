# 【テストID】T017 — S04の編集・取消と権限による表示制御

## 【目的】

* S04が予約詳細を表示し、予約者本人・管理者・第三者で編集/取消ボタンの表示が切り替わること、更新・取消がAPIと正しく連携することを確認する。

## 【参照テスト計画】

* `docs/P006-test-plan.md` 4.2(Sprint 4)、3.1 V-F-05 / V-F-10 / V-F-12
* 仕様: `docs/P002-frontend-spec.md` 3.4・2.4・4・5.7

## 【対象モジュール】

* `client/src/views/s04-reservation-detail.js`、`client/src/components/reservation-form.js`、`client/src/lib/api.js`

## 【前提条件】対象スプリントの全モジュールビルドが成功していること

* Sprint 4 のクライアント単体テストが全件PASSしていること。

## 【使用するテストデータ】

* `user001` の予約(「本日+1日」会議室A 10:00-11:00、参加者 `user002`、参加予定人数なし)。利用者: `user001` / `user002` / `admin001`。

## 【事前準備】

1. DBファイルを削除し、サーバーを起動し、基準データセットと上記予約を投入する。

## 【実行手順】

1. `user001` でログインし、S04を開く。表示項目を確認する。
2. 編集モードに入り、件名を「臨時会議」に変更して更新する。
3. 取消ボタンを押し、確認ダイアログでキャンセルを選ぶ。
4. 再度取消ボタンを押し、OKを選ぶ。
5. `user002` でログインし、`user001` の別の予約のS04を開く。
6. `admin001` でログインし、同じ予約のS04を開く。
7. 存在しない `reservation_id` でS04を開く。
8. ※CR-001: オンライン会議URL(`https://example.com/meet/t017`)が登録済みの予約のS04を開き、閲覧モードの表示を確認する。
9. ※CR-001: 手順8の予約で編集モードに入り、オンライン会議URLの初期値を確認したうえで、空欄に変更して更新する。更新後に再度S04を開く。
10. ※CR-001: 手順8の予約で編集モードに入り、オンライン会議URLに `example.com/meet`(スキームなし)を入れて更新を押す。

## 【実行コマンド】

* `cd client && node --test tests/integration/test_t017_detail_edit_cancel.js`

## 【期待結果】

* 手順1: 会議室名・日付・時間帯・件名・参加者(鈴木 花子)・参加予定人数「-」・**オンライン会議URL「-」(※CR-001。基準データセットの予約は未登録)**・備考・予約者名が表示され、編集・取消ボタンがある。
* 手順2: `PUT` が呼ばれ、`#/calendar` へ戻り「予約を更新しました。」が表示される。
* 手順3: `DELETE` が呼ばれない。
* 手順4: `DELETE` が呼ばれ、`#/calendar` へ戻り「予約を取り消しました。」が表示される。
* 手順5: 詳細は表示されるが、**編集・取消ボタンが無い**。
* 手順6: 編集・取消ボタンが表示される。
* 手順7: 「対象のデータが見つかりません。削除された可能性があります。」が表示される。
* 手順8(※CR-001): オンライン会議URLの行に `a` 要素が1つ描画され、`href` が `https://example.com/meet/t017` と一致し、表示文字列もそのURLである。`target="_blank"` / `rel="noopener noreferrer"` が付いている。
* 手順9(※CR-001): 編集モードの入力欄の初期値が `https://example.com/meet/t017` である。空欄で更新すると `PUT` が呼ばれ(`meeting_url` が `""`)、再表示したS04ではオンライン会議URLが「-」になり `a` 要素が無い。
* 手順10(※CR-001): `PUT` は呼ばれず、オンライン会議URL欄の直下に「オンライン会議URLは http:// または https:// で始まるURLを入力してください。」が表示される。
