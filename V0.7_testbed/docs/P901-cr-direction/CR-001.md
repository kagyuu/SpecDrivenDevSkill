# CR-001 — 予約にオンライン会議URLを登録できるようにしてほしい

## 起票日

2026-08-05

## 起票者

利用者からのフィードバック(詳細不明) — 会話で口頭により示された要望。依頼者の氏名・所属、および元になったチケット/議事録は特定できていない。★FIXME★ 起票元(依頼者の氏名・役職、チケット番号、議事録)が特定できていないため出所を「詳細不明」とした。運用上の追跡が必要であれば人間が補記すること。

## 背景・課題

* ハイブリッド会議(会議室に集まる参加者と、オンラインで参加する参加者が混在する会議)が増えている。
* 現状、予約にオンライン会議のURLを保持する項目が無いため、会議室を予約した人は URL を別の手段(メール・チャット)で共有するか、「備考」欄に本文として書き込むしかない。
* 「備考」欄に書いた場合、S04(予約詳細)ではプレーンテキストとして表示されるだけでクリックできず、参加者が URL をコピーして貼り直す手間が発生している。

## 変更要求の内容

* 予約(`reservations`)に **オンライン会議URL** を任意入力項目として追加する。
* **画面**
  * S03 予約作成画面(`docs/P002-frontend-spec.md` 3.3)に、オンライン会議URLの入力欄を**任意入力**として追加する。
  * S04 予約詳細・編集画面(`docs/P002-frontend-spec.md` 3.4)に、閲覧モードでの表示と、編集モードでの入力欄を追加する。閲覧モードでは、登録済みのURLを**クリックできるリンクとして表示**する。
  * S02 予約カレンダー画面(`docs/P002-frontend-spec.md` 3.2)には**表示しない**(明示的に対象外)。
* **入力ルール**
  * 任意入力。空欄のままでも予約の登録・更新ができる。
  * 最大500文字。
  * 入力する場合は `http://` または `https://` で始まっていなければエラーとする。
* **API**: API-14 / API-15 / API-16 の `Reservation` 表現(`docs/P002-frontend-spec.md` 5.3)と、API-15 / API-16 のリクエスト(同 5.7)に項目を追加する。
* **データモデル**: `reservations` テーブル(`docs/P002-frontend-spec.md` 6.2)に列を追加する。既存の予約データは保持したまま列を追加する(既存行はURL未登録として扱う)。

## 期待する振る舞い

* S03 の入力フォームに「オンライン会議URL」欄が任意入力として表示される。
* S03 でオンライン会議URLを空欄のまま登録すると、予約が登録できる(エラーにならない)。
* S03 で `https://` で始まるURL(例: `https://example.com/meet/abc`)を入力して登録すると、その値が予約に保存される。
* S03 で `http://` で始まるURLを入力して登録すると、その値が予約に保存される。
* S03 / S04 で `http://` `https://` のいずれでも始まらない値(例: `example.com/meet`、`ftp://example.com`)を入力して送信すると、エラーメッセージが表示され、予約は登録・更新されない。
* S03 / S04 で 501文字以上のURLを入力して送信すると、エラーメッセージが表示され、予約は登録・更新されない。
* S03 / S04 で 500文字ちょうどのURL(`https://` で始まる)は正常に登録・更新できる。
* S04 の閲覧モードで、オンライン会議URLが登録されている予約を開くと、URLがクリック可能なリンク(`a` 要素で、リンク先がそのURL)として表示される。
* S04 の閲覧モードで、オンライン会議URLが未登録の予約を開くと、「-」が表示される(リンクは表示されない)。★FIXME★ 未登録時の表示文字は要望に指定がないため、S04の既存項目「参加予定人数(未入力なら「-」)」の規約に合わせて「-」と仮定した。
* S04 の編集モードで、既存の予約のオンライン会議URLが入力欄の初期値として表示され、書き換え・空欄化(URLの削除)ができる。
* S02 予約カレンダー画面のセルにはオンライン会議URLを表示しない。
* API-14 / API-15 / API-16 のレスポンスの `Reservation` にオンライン会議URLが含まれる。
* 既にDBに存在する予約(オンライン会議URLを持たない予約)を、この変更の後も参照・更新でき、URLは未登録として扱われる。

## 影響が想定される範囲

P901時点での見積もりであり、確定した対応範囲ではない(確定は P903 が `docs/P903-cr-records/CR-001.md` に記録する)。

* 画面: S03(入力欄追加)、S04(閲覧表示 + 編集入力欄追加)。S02 は対象外(要望で明示的に除外)。S05 は列構成の変更が無いため対象外。
* API: API-15(POST リクエスト項目追加)、API-16(PUT リクエスト項目追加)、API-14(レスポンス項目追加)、API-12 / API-13(`Reservation` 表現を共有するためレスポンスに項目が現れる)。
* データモデル: `reservations` に列追加(`ALTER TABLE reservations ADD COLUMN`)。新しいマイグレーションファイル `004-*.sql` の追加が必要。
* 関連ADR: ADR-009(スキーマ適用方式 = 差分適用型マイグレーション + `schema_migrations`)。**本CRは ADR-009 に抵触しない。** ADR-009 はまさに「後からのカラム追加」を安全に行うために差分適用型を選んだ決定であり、本CRはその決定に**従って**新規マイグレーションファイルを追加する。既存ADRを覆す要望は含まれていない。
* 関連ADR: ADR-002(バリデーションの実装方式)、ADR-008(予約の物理削除)には影響しない。

## 優先度の判断理由

* 影響度: **高**。予約の作成・編集は本システムの主要機能であり、全利用者が使う画面(S03 / S04)に関わる。
* 緊急度: **低**。オンライン会議URLは既存の「備考」欄にテキストとして書くという回避策が現に運用されており、業務が停止するような実害は発生していない(不便さの解消が主目的)。
* ルーブリック(影響度: 高 × 緊急度: 低)より、優先度は **中** と仮置きした。★FIXME★ 優先度は人間からの指示が無いためAgentがルーブリックにより仮置きした。「備考欄での回避が実運用として許容できない」等の事情があれば人間が `docs/CR.md` の優先度列を変更すること。

## 備考

* 要望では「オンライン会議URL」という日本語の項目名のみが示されており、API/DB上のフィールド名は指定されていない。命名は P002 / P003 で確定する。
* URLの形式チェックとして要望が指定しているのは「`http://` または `https://` で始まること」だけである。ホスト名の妥当性やドメインのホワイトリストは要求されていない。
